# Scope comparison and differentiation

This short comparison was refreshed from the live public resource listing and repository sources on 2026-09-29 evening in America/Chicago (2026-09-30 01:49–01:54 UTC), with a public Scigantic notebook UI review by the principal reviewer through approximately 02:01 UTC. It is a bounded product-scope assessment, not a claim of ownership, priority, completeness, organizer endorsement, or award eligibility. Public resources can change after that date.

- [`veckit`](https://github.com/aristoteleo/veckit) is the authoritative local scorer that ScoreLens pins and calls. ScoreLens adds no replacement scalar or scorer calibration.
- [VecBench](https://github.com/AJK0921/vecbench/tree/04d5d641df487bbff740d0e14b5b5b1a3e84434c/vecbench) already accepts users' predictions and provides aggregate scorer calibration, noise, stability, and fidelity workflows. Its metric tables retain raw values. ScoreLens does not replace those workflows or claim their calibration and rankability functions.
- [Local Scoring Wrapper for veckit](https://github.com/xxx12e/vec-community-kit/tree/afd3cfac37978fb18bbdee692c369c4b65ea6c71/vec_local_score) already supports supplied prediction/target/reference or WT files for all three tasks, seeded sampling, a frozen target probe, scorer version/file-hash provenance, and multi-seed summaries. It documents the same tested scorer pin. Local input support, scorer pinning and provenance are not unique to ScoreLens.
- [Virtual Embryo Intuition Lab](https://github.com/i-habib/virtual-embryo-community/tree/939b669a84ddc168f1e68dc9b0b8885d4bd35ab0/intuition-lab) teaches controlled T1/T2/T3 failure modes, including population collapse, expression-location scrambling and WT-relative response scale/reversal, and audits the scorer's spatial-frame issue. Its scoring helpers accept mappings of supplied prediction paths and it pins the same scorer. These concepts and user-file support are established; ScoreLens's narrower increment is the named evidence exported for a particular bounded comparison, not the controlled examples themselves.
- [Virtual Embryo Submission Viewer](https://github.com/Shashwat-srivastav/Virtual-Embryo-Submission-Viewer/tree/fea3f8812db9fadb3457e4af11014ed3778a32dd) already visualizes users' predictions and diagnoses partial spatial coverage, scale and origin problems against a supplied source stage. ScoreLens's spatial metric evidence overlaps that practical diagnostic purpose, but is not a general viewer, registration tool, laterality test, or spatial coverage validator.
- [Scigantic's Task 1 first-submission tutorial](https://scigantic.com/sample/virtual-embryo-challenge-t1) teaches user-provided E8.5/E9.5 input inspection, a mean-shift baseline, aggregate local `veckit` scoring, and current-contract submission preparation. The displayed notebook sections inspected by the principal reviewer did not expose the named gene/probe/pair/residual ledger bundle described here. This comparison is based on a read-only public UI review, not a pinned notebook source clone or an executed test.

The narrow intended contribution is the integrated evidence report: named selected-sample gene and frozen-probe class terms; an occurrence-weighted sampled pair ledger; T3 matched-WT response residuals and severity gates; and constrained spatial metric terms for T2/T3. The inspected comparator implementations expose metric tables, controlled-failure experiments, or coverage/frame diagnostics rather than this same ledger bundle. This is a limited source comparison, not a claim that no other implementation exists. These are evidence tables with stated A/B/C/D classes, not new official metrics, a hidden-score forecast, biological-causality finding, or general diagnostic certification. T2/T3 overlap with existing spatial tooling remains material; any claim must preserve the selected scope, coordinate-frame caveat, and no-registration boundary.

The official [Community resources index](https://virtualembryo.ai/challenge/resources) remains the current primary listing. Its [award guidance](https://virtualembryo.ai/challenge/community) gives greater weight to earlier-filed overlapping work. This document does not assert an exhaustive implementation review, priority over filed work, deployment, adoption, or award acceptance.
